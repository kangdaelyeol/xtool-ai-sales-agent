# AI 영업 상담 에이전트 — 직접 구축 기술 설계

업체(vox.ai, ElevenLabs)를 쓰지 않고 기초 모델을 조합해 **우리가 직접 만들기 위한** 기술 문서입니다. 아래 순서로 다룹니다.

1. 벤치마킹 업체들이 실제로 무엇으로 만들었는지
2. 우리가 쓸 부품(STT, LLM, TTS, 턴 감지, 전화망)과 구조
3. 우리가 직접 만들어야 하는 기능 목록과 개발 순서

> - 업무 쪽 내용(적용 업무, 판정 기준, 대화 설계, 법무)은 originalshq 레포의 [업무 문서 README](../../originalshq/docs/ai-sales-agent/README.md)에 있습니다. 이 문서는 기술만 다룹니다. (레포 간 링크는 두 레포를 같은 폴더에 나란히 둔다는 전제입니다.)
> - 2026-11-03에 공식 문서, 공개 API 스펙, 공개 GitHub, 채용 공고를 보고 조사했습니다.
>   - **(확인)**: 출처에 그대로 적힌 내용입니다.
>   - **(추정)**: 정황으로 판단한 내용입니다.
>   - 지연·품질 수치는 업체 발표값이라 **우리 환경에서 다시 재야 합니다.**
> - 모델 이름과 가격은 자주 바뀝니다. 개발을 시작할 때 다시 확인해야 합니다.

## 1. 한눈에 보기

- **업체들도 기초 모델을 직접 만들지 않습니다.** vox.ai와 ElevenLabs 모두 아래 네 부품을 이어 붙인 구조입니다.
  - 음성 인식(STT)
  - 대화 생성(LLM)
  - 음성 합성(TTS)
  - 말 차례 판단(턴 감지)
- **vox.ai는 오픈소스 LiveKit Agents를 고쳐서 만들었습니다.** 공개 GitHub와 SDK로 확인했습니다.
  - LLM은 GPT, Claude, Gemini, DeepSeek, GLM 같은 외부 모델을 골라 씁니다.
  - TTS는 ElevenLabs, Cartesia, Google, OpenAI를 씁니다.
  - 차별점은 모델이 아닙니다. **한국어 턴 감지 튜닝, 국내 전화망, 운영 기능**(분석, 테스트, 대량 발신)입니다.
- **그래서 우리도 같은 방식으로 만들 수 있습니다.** 우리가 만들 것은 모델이 아니라 부품을 잇고 우리 업무(Monday, 방문체험 예약)에 맞추는 부분입니다.
- **추천 구성 (실측 후 확정):**

  | 부품 | 추천 |
  |---|---|
  | 프레임워크 | **LiveKit Agents (TypeScript)** |
  | STT | **리턴제로(RTZR)** 전화용 모델 |
  | LLM | **Claude Haiku 5.5** 또는 **GPT-6 Luna** (생각 모드 끔) |
  | TTS | **ElevenLabs v4 Turbo / Flash v2.5** (대안 Typecast) |
  | 전화망 | **국내 SIP 회선 + 중계 서버(Asterisk)** |

- **가장 큰 장애물은 전화 회선입니다.**
  - Twilio 같은 해외 통신사로 한국 휴대폰에 걸면 국제전화로 표시되거나 막힙니다.
  - 국내 통신사(KT·SKB·LGU+ 또는 국내 통신 API 업체)와 회선 계약이 필요합니다.
  - **모델 선택보다 먼저 견적과 기술 조건을 받아야 합니다.**
- **비용:** 모델 비용은 분당 30원 안팎, 회선을 포함하면 **분당 약 110~140원**입니다(추정). vox 공개 가격은 분당 약 340원입니다. 대신 개발과 운영 인력이 듭니다.

### 2-3. 정리: 무엇을 가져오나

| 구분 | 업체가 한 것 | 우리가 할 것 |
|---|---|---|
| 기초 모델 (STT/LLM/TTS) | 외부 API 조합. 일부는 자체 호스팅 | **외부 API 조합** (나중에 일부 자체 호스팅 검토) |
| 실시간 파이프라인 | LiveKit Agents 포크 | **LiveKit Agents 그대로 사용** + 설정 튜닝 |
| 한국어 턴 감지 | 자체 모델 + 적응형 튜닝 | LiveKit 내장 턴 감지·끼어들기 모델 + **맞장구 무시어, 대기 시간 튜닝** |
| 전화망 | 자체 SIP + 국내 번호 | **국내 회선 + 중계 서버** |
| 운영 기능 | 대량 발신, 분석, 테스트, 대시보드 | **우리 업무에 필요한 것만** (7장) |
| 업무 연동 | 웹훅 | **Monday·Firestore·Solapi와 직접 연결** (업체보다 유리한 부분) |

## 3. 구조 선택: 단계 연결형 vs 음성 직통형

| 항목 | 단계 연결형 (STT → LLM → TTS) | 음성 직통형 (Realtime) |
|---|---|---|
| 대표 모델 | 부품을 각각 고름 | OpenAI `gpt-live-1`(2026-09), `gpt-realtime-2.1`, Google `gemini-3.8-live` |
| 한국어 부품 선택 | 자유 (RTZR, Typecast 등 국내 업체 가능) | 모델에 고정 |
| 제품명 인식·발음 | 키워드 부스팅과 발음 변환으로 강하게 제어 | 프롬프트로만 제어 |
| 대화 기록·감사 | 텍스트가 단계마다 남아 필터링·기록이 쉬움 | 별도 받아쓰기 필요 |
| 목소리 | 직원 목소리 복제 가능 | 정해진 음성 위주 |
| 자연스러움 (끼어들기) | 직접 튜닝해야 함 | 좋음 |
| 지연 | 약 0.8~1.4초 | 약 0.8~1.5초 |
| 분당 모델 비용 | 약 $0.01~0.035 | 약 $0.015~0.07 |
| 구축 난이도 | 중간 (프레임워크 사용) | 낮음 |

**추천: 단계 연결형.**
- vox와 같은 방식입니다.
- 영업 통화에서는 **제품명("F2 울트라", "메탈팹", "엑스툴")과 가격을 정확히 듣고 말하는 것**이 중요합니다. 단계 연결형이 이 부분을 제어하기 쉽습니다.
- 대화 기록 대응도 쉽습니다.

**음성 직통형은 비교용으로만 테스트합니다.**
- `gpt-live-1`은 발신 SIP를 직접 지원하고 대화 전환이 0.8초 수준이라는 2차 자료가 있습니다.
- 다만 국내 회선이 TLS·SRTP·Opus를 지원해야 하고, 한국어 품질 공식 자료는 없습니다.

## 4. 부품 선택

### 4-1. 프레임워크

| 후보 | 언어 | 장점 | 단점 |
|---|---|---|---|
| **LiveKit Agents** ★ | Python, **TypeScript** | 우리 팀 언어(TS)를 공식 지원합니다. 한국어 턴 감지, 맞장구·끼어들기 구분 모델, 자동응답 감지, SIP 발신·전환이 다 들어 있습니다. vox가 쓰는 것과 같습니다. | TS 버전은 일부 기능이 Python보다 늦습니다(IVR 자동 탐색 등, 우리에겐 불필요). **SIP 등록(REGISTER) 방식을 지원하지 않습니다.** |
| Pipecat | Python만 | 커뮤니티가 가장 크고, Smart Turn(한국어 포함 23개 언어)이 있습니다. | 서버를 Python으로 따로 운영해야 합니다. |
| jambonz | Node.js | 어떤 SIP 회선이든 붙고 등록 방식도 지원합니다. | 턴·끼어들기 모델 품질은 LiveKit이 앞섭니다. |
| Vocode | Python | — | 2026년 개발이 둔화됐습니다. |

**LiveKit 운영 방식**
- **LiveKit Cloud**
  - 요금: Build 무료(1,000분), Ship 월 $50(5,000분 포함, 이후 분당 $0.01).
  - 에이전트를 올릴 수 있는 리전은 미국, 유럽, 뭄바이뿐입니다. 서울·도쿄는 없습니다.
  - 미디어와 SIP는 일본 리전을 쓸 수 있습니다.
- **추천 조합:** 에이전트 워커는 **GCP 서울에 직접** 띄우고, 미디어와 SIP는 LiveKit Cloud 일본 리전에 고정합니다. 지연이나 데이터 위치가 문제되면 LiveKit 서버도 서울 VM에 직접 운영합니다(오픈소스).

### 4-2. STT (음성 인식)

| 후보 | 장점 | 확인할 점 | 가격 |
|---|---|---|---|
| **리턴제로 `sommers_ko`** ★ | **전화용 도메인 모델**이 있고, 8kHz μ-law를 그대로 받습니다. 한글 키워드 부스팅("엑스툴", "에프투 울트라", "메탈팹")이 됩니다. 확정 결과를 바로 받는 명령(FINALIZE)이 있습니다. LiveKit 플러그인이 있습니다. | 국내 업체라 국외 이전 문제가 없습니다. | 시간당 ₩1,000 (분당 약 17원), 월 1,000시간 초과분은 ₩500 |
| Soniox `stt-rt-v5` | 가장 쌉니다. 한국어 정확도 주장이 좋습니다(자체 벤치마크). 문맥으로 제품명을 주입할 수 있습니다. | 8kHz 전화 음성 품질 | 시간당 $0.12 (분당 약 3원) |

| Deepgram Nova-3 (ko) | 2026-08에 한국어 개선. 빠른 차세대 모델 Flux는 **한국어 미지원** | 한국어 키워드 기능이 동작하는지 | 분당 $0.0077 |
| 네이버 Clova Speech | 국내 업체, 부스팅 지원 | 공식 단가, 8kHz 지원 여부 | 미확인 |

→ **실제 우리 상담 녹음 50~100건으로 리턴제로와 Soniox를 비교**해서 정합니다. 기준은 제품명 인식률, 전화번호와 숫자 인식, 지연입니다.

> **주의 (2026-11-03 확인):** 리턴제로의 LiveKit 플러그인은 **Python용만** 있습니다. TypeScript로 쓰려면 연결 코드를 직접 옮겨 짜야 합니다. Soniox는 TS 플러그인이 있어 PoC에서는 Soniox로 먼저 시작합니다. Typecast는 두 언어 모두 플러그인이 없습니다. 구독과 설치 순서는 [poc-setup.md](poc-setup.md)에 있습니다.

**LLM 사용 원칙**
- **생각(thinking) 모드는 끕니다.** 실측에서 생각 모드가 지연의 주범이었습니다.
- 시스템 프롬프트와 지식은 **캐시**합니다.
- 통화 중에는 빠른 모델로 답하고, **통화 후 요약·판정 추출은 더 좋은 모델로 따로** 돌립니다(지연과 무관하므로).
- vox와 ElevenLabs처럼 **백업 모델을 둡니다.** 첫 토큰이 일정 시간 안에 안 오면 다른 제공자로 넘깁니다.
- 우리 지식(기기 소개, 가격, FAQ)은 수만 자 수준이라 **처음에는 RAG 없이 프롬프트에 그대로** 넣습니다. vox도 1만 토큰 미만은 그대로 넣습니다.

### 4-5. 턴 감지와 끼어들기

한국어는 "네", "음", "아" 같은 **맞장구가 잦은 언어**입니다. 단순히 소리만 감지하면 AI가 자꾸 말을 멈춥니다. vox가 가장 공들인 부분도 여기입니다.

| 단계 | 사용할 것 | 근거 |
|---|---|---|
| 소리 감지 | Silero VAD (30ms 처리에 1ms 미만, 8kHz 지원) | (확인) |
| 말 끝 판단 | LiveKit 오디오 턴 감지 모델 (한국어 포함 14개 언어) | (확인) 한국어 정확도는 미공개 |
| 맞장구와 끼어들기 구분 | LiveKit Adaptive Interruption | (확인) 영어에서 더 낫다고 명시 |
| 우리가 튜닝할 것 | 맞장구 무시어 목록("네", "예", "음", "아", "그렇죠"), 끼어들기 최소 길이 약 0.5초, "아니요"·"잠깐만요" 같은 말은 즉시 멈춤, 전화번호를 불러줄 때는 더 기다림 | vox·ElevenLabs 설정 참고 |

- 참고: 말 끝 판단 대기를 0.3초로 짧게 잡으면 말이 중간에 잘리는 비율이 40~52%였다는 실측이 있습니다. vox 기본 무음 기준은 0.5초입니다.

### 4-6. 자동응답·음성사서함 감지

부재중이면 통신사 안내("전화를 받을 수 없어…", 소리샘)가 나옵니다. 이걸 사람으로 착각하면 AI가 혼자 떠듭니다.

1. **SIP 응답 코드로 먼저 거릅니다.** 통화 중(486), 응답 없음(480) 등. 연결 전 미리 나오는 안내음(early media)은 대화로 취급하지 않습니다.
2. **연결 후 키워드로 빠르게 판정합니다.** "소리샘", "음성사서함", "삐 소리 후", "전원이 꺼져", "받을 수 없어"
3. **애매하면 LiveKit 자동응답 감지에 한국어 프롬프트를 넣어** 판정합니다.
4. **사서함이면 끊습니다.** 대신 문자(Solapi)를 보내고 재시도 일정을 잡습니다.
5. 처음 2~4주는 실제 녹음을 모아 기준을 조정합니다.

## 5. 전화 회선: 가장 큰 장애물

### 5-1. 해외 통신사는 안 됩니다

| 사업자 | 문제 |
|---|---|
| Twilio | 한국 번호는 한국 사업자등록 기업만 개통할 수 있고, 국내 번호 표시가 보장되지 않습니다. |
| Vonage | 해외 발신은 "006 1415…"처럼 국제전화 식별번호가 붙어 표시됩니다. |
| Retell (해외 AI 콜 업체) | 한국 발신을 지원하지 않습니다(2026-05). 직접 SIP로 우회하라고 안내합니다. |

- 방통위 가이드라인에 따라 **해외 발신 전화는 휴대폰에 00X가 붙어 표시**됩니다.
- 2026년 5월 해외 번호를 국내 번호로 위장하는 행위를 금지하는 법 개정안이 국무회의를 통과했습니다(위반 시 3년 이하 징역).
- **결론: 회사 번호로 걸려면 국내 통신사 회선이 필수입니다.**

### 5-2. 국내 선택지

| 선택지 | 내용 | 확인 수준 |
|---|---|---|
| KT 기업 인터넷전화 / SIP 트렁크 | 070 기본료 2,000~4,000원, 통화료 초당 1.5원(VAT 별도). 인증은 ID/PW, 고정 IP, SBC 연동 중 선택 | 대리점 페이지 기준, 공식 견적 필요 |
| SK브로드밴드 교환기형 | 채널당 월 2,000원, 30채널 단위 | 판매 대행 페이지 기준 |
| LG U+ | 자체 AI 콜봇 상품이 있습니다(OpenAI 기반, 2025-12). SIP 상품 상세는 미확인 | 미확인 |
| 한국AI통신 (ClawOps) | REST API로 070·대표번호를 발급합니다. 모든 요금제에 SIP 포함, AWS 서울, 월 ₩19,000~99,000 | **업체 홍보 자료 기준, 검증 필요** |
| Solapi 음성 메시지 | TTS 단방향 발송만 됩니다. 실시간 대화에는 쓸 수 없습니다. | 확인 |

### 5-3. 연결 방법

LiveKit SIP는 **등록(REGISTER) 방식을 지원하지 않습니다.** 국내 회선은 ID/PW 등록 방식이 많습니다. 그래서 중간에 중계 서버를 둡니다.

```
국내 회선 (KT/SKB/LGU+ 등)
   ⇅  등록 방식, G.711 A-law
[중계 서버] GCE 서울 VM, 고정 공인 IP — Asterisk(또는 jambonz)
   ⇅  IP 인증 SIP, 코덱 변환, NAT·SRTP 처리
[LiveKit SIP]
```

- 고정 IP 인증 회선이면 LiveKit SIP에 바로 붙일 수도 있습니다. 하지만 코덱, NAT, 암호화 차이를 흡수하려면 **중계 서버를 두는 쪽이 안전합니다.**
- 나중에 대표번호 인바운드를 붙일 때도 중계 서버에서 라우팅만 추가하면 됩니다.
- 참고 사례: 국내 공공 프로젝트(GovTech-Korea)도 Asterisk + 070 연동이 어려워 MVP에서 뺐습니다. **회선 연동은 일정에 여유를 둬야 합니다.**

### 5-4. 통신사에 물어볼 것

> 요구 사항 상세, 문의 메일 초안, 세팅 순서는 [telephony-setup.md](telephony-setup.md)에 있습니다.

1. 최소 채널 수 (1~2채널 계약 가능한지)
2. 인증 방식 (고정 IP / ID·PW 등록)
3. 지원 코덱 (G.711 A-law/μ-law, Opus), 암호화(SRTP) 지원
4. 발신번호로 대표번호나 02 번호를 쓸 수 있는지, 레터링(상호 표시) 가능 여부
5. 동시 통화 수
6. **AI 콜봇·자동 발신 용도를 약관상 허용하는지**
7. 통화료 (휴대폰 발신 단가)

### 5-5. 받는 비율 올리기

- 070보다 **대표번호나 02 번호**가 받는 비율이 높을 것으로 봅니다(추정).
- KT 발신정보알리미 같은 상호 표시 서비스를 씁니다.
- 문의 직후 Solapi로 **"오리지널스에서 곧 전화드립니다" 문자를 먼저 보냅니다.**
- 후후·T전화에 업체 정보를 등록합니다(절차 확인 필요).

## 6. 전체 아키텍처

```
[웹사이트 문의 폼]
   │
   ▼
functions-xtool / submitInquiry  (지금: Firestore 저장 → Monday 생성 → 접수 문자)
   │  추가: 발신 조건 검사 (동의, 발신 시간 08~21시, 수신 거부, 중복, 테스트 문의)
   ▼
[발신 큐] Firestore calls/{id}  ← 밀린 콜백 배치도 여기로 넣음
   │  Cloud Functions가 LiveKit API로 에이전트 배정 + SIP 발신 요청 (짧은 작업만)
   ▼
[LiveKit]  미디어 + SIP  (LiveKit Cloud 일본 리전, 또는 서울 VM 직접 운영)
   ⇅
[중계 서버] Asterisk, GCE 서울 VM  ⇄  국내 SIP 회선  ⇄  고객 휴대폰
   ⇅
[에이전트 워커] LiveKit Agents (TypeScript), GKE Autopilot 또는 GCE 서울
   ├ Silero VAD + 턴 감지 + 끼어들기 구분 + 자동응답 감지
   ├ STT (리턴제로) → LLM (Haiku 5.5 / GPT-6 Luna) → 발음 변환 → TTS (ElevenLabs)
   ├ 통화 중 도구 → functions-xtool API
   │    · 고객·문의 정보 조회
   │    · 방문체험 빈 시간 조회와 예약
   │    · 상담사 연결 (업무 시간만)
   │    · 수신 거부 등록 / 통화 종료
   └ 통화 종료 → 녹음·대화록 저장
   ▼
[통화 후 처리] functions-xtool
   ├ 좋은 모델로 요약 + 판정 칸 추출 (README 6-2)
   ├ Firestore 통화 기록 저장
   ├ Monday 상태·컬럼 갱신, 업데이트 글로 요약 등록, 담당자 알림
   ├ 부재·사서함이면 Solapi 문자 + 재시도 예약
   └ 리드 매니저 통계에 반영
```

**호스팅 원칙**

| 구성 요소 | 호스팅 | 이유 |
|---|---|---|
| 발신 요청, 결과 처리, Monday·Solapi 연동 | **Cloud Functions** (기존 functions-xtool) | 짧은 이벤트 처리 |
| 에이전트 워커 | **GKE Autopilot 또는 GCE (서울)** | 통화가 수 분씩 이어집니다. Cloud Functions/Cloud Run은 긴 실시간 세션에 맞지 않습니다. 배포할 때 진행 중인 통화가 끝날 때까지 기다리는 설정(drain)이 필요합니다. |
| 중계 서버 | **GCE VM (서울, 고정 공인 IP)** | SIP/RTP는 UDP와 고정 IP가 필요합니다. |
| 코드 위치 | **별도 레포 `xtool-ai-sales-agent`**(이 레포)에 에이전트 워커, 배포 설정, 기술 문서를 둡니다. 업무 연동과 검수 화면은 originalshq에 둡니다. | functions와 배포 단위가 다릅니다. 두 레포는 같은 Firebase 프로젝트의 Firestore(예: `calls/{id}`)와 functions-xtool API(공유 비밀키 인증)로 연결합니다. |

## 8. 응답 지연 예산

**목표: 고객 말이 끝나고 AI가 말을 시작할 때까지 1초 안팎.** 업체 수준은 0.6~0.95초입니다.

| 구간 | 목표 | 줄이는 방법 |
|---|---|---|
| 말 끝 판단 | 0.3~0.5초 | 턴 감지 모델로 짧게 판단하되 맞장구는 무시 |
| STT 확정 | 0.15~0.3초 | 스트리밍, 말 끝나면 바로 확정 요청 |
| LLM 첫 토큰 | 0.2~0.4초 | 생각 모드 끔, 프롬프트 캐시, 아시아 리전이나 빠른 제공자 |
| TTS 첫 음성 | 0.1~0.2초 | 문장 단위로 끊어 바로 합성, **TTS 연결을 미리 열어 둠** |
| 네트워크 | 0.05~0.1초 | 워커·STT·TTS를 가까운 리전에 |

- 실측 사례에서는 **TTS가 전체 지연의 60~85%를 차지**했습니다.
- 부품들을 같은 리전에 모으자 1.6초에서 크게 줄었다는 사례도 있습니다.
- 서울에서 미국 API까지 왕복으로 약 150~200ms가 더해집니다.
- **구간별 지연을 매 통화 기록**해서(vox도 함) 병목을 찾습니다.
- 도구를 호출하는 동안(예약 조회)은 "잠시만요, 확인해 볼게요"를 말해 공백을 메웁니다.

## 10. 개발 단계

| 단계 | 기간(안) | 할 일 | 끝났다는 기준 |
|---|---|---|---|
| **0. 회선 견적 (바로 시작)** | 병행 | 5-4 질문으로 KT·SKB·LGU+·한국AI통신에 견적과 기술 조건 문의. 동의 문구 법무 검토 | 회선 업체와 연결 방식 결정 |
| **1. 브라우저 PoC** | 1~2주 | LiveKit Cloud(무료) + 브라우저 통화로 한국어 대화 프로토타입. STT 2개, TTS 2개, LLM 2개를 바꿔 끼우며 비교 | 한국어 자연스러움과 지연 1초 안팎 확인. 부품 확정 |
| **2. 전화 연결** | 2~4주 | 중계 서버(Asterisk) 구축, 국내 회선 연결, 직원 휴대폰으로 발신 테스트, 사서함·안내 멘트 샘플 수집 | 직원 번호로 안정적으로 통화됨 |
| **3. 업무 연동** | 2~3주 | 발신 큐, submitInquiry 연결, 통화 중 도구(예약), 통화 후 분석, Monday·Solapi 반영, 검수 화면 | 테스트 문의로 처음부터 끝까지 동작 |
| **4. 파일럿** | 4주 | [업무 문서 README 9장](../../originalshq/docs/ai-sales-agent/README.md#9-단계별-로드맵) 파일럿 (기기 보드 1~2개, 업무 시간 외 접수분, 절반만 AI) | 지표를 기준값과 비교 |
| **5. 고도화** | 이후 | 턴 튜닝, 시나리오 테스트, 대시보드, 밀린 콜백 배치, 인바운드 | |

- STT 자체 호스팅: Whisper 계열을 우리 녹음으로 미세 조정. vox도 그렇게 한 것으로 보입니다.
- LLM 자체 호스팅: gpt-oss 등 오픈 모델
- 자체 턴 감지 모델: 우리 통화 데이터로 학습
