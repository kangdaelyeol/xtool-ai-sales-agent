## 1. 한눈에 보기

- **업체들도 기초 모델을 직접 만들지 않습니다.** vox.ai와 ElevenLabs 모두 아래 네 부품을 이어 붙인 구조입니다.
  - 음성 인식(STT)
  - 대화 생성(LLM)
  - 음성 합성(TTS)
  - 말 차례 판단(턴 감지)
- **vox.ai는 오픈소스 LiveKit Agents를 고쳐서 만들었습니다.** 공개 GitHub와 SDK로 확인했습니다.
  - LLM은 GPT, Claude, Gemini, DeepSeek, GLM 같은 외부 모델을 골라 씁니다.
  - TTS는 ElevenLabs, Cartesia, Google, OpenAI를 씁니다.
  - 차별점은 모델이 아닙니다. **한국어 턴 감지 튜닝, 국내 전화망, 운영 기능**(분석, 테스트, 대량 발신)입니다.
- **그래서 우리도 같은 방식으로 만들 수 있습니다.** 우리가 만들 것은 모델이 아니라 부품을 잇고 우리 업무(Monday, 방문체험 예약)에 맞추는 부분입니다.
- **추천 구성 (실측 후 확정):** 가운데 칸이 처음 계획이고, 오른쪽 칸이 PoC를 거친 지금 코드입니다.

  | 부품 | 추천 (2026-11-03 계획) | 지금 코드 (2026-11-08) |
  |---|---|---|
  | 프레임워크 | **LiveKit Agents (TypeScript)** | 같음. `@livekit/agents` 1.9.5 |
  | STT | **리턴제로(RTZR)** 전화용 모델 | Soniox `stt-rt-v5`. 리턴제로는 TypeScript 플러그인이 없어 PoC에서 먼저 Soniox로 시작했습니다(4-2) |
  | LLM | **Claude Haiku 5.5** 또는 **GPT-6 Luna** (생각 모드 끔) | Claude Haiku 5.5(`claude-haiku-5-5`), 생각 모드 끔, effort low. 한 차례 비교에서 GPT-6 Luna보다 빠르고 일관적이었습니다(표본이 작음, 4-3) |
  | TTS | **ElevenLabs v4 Turbo / Flash v2.5** (대안 Typecast) | ElevenLabs `eleven_v4_turbo`. Typecast 비교는 아직입니다(4-4) |
  | 전화망 | **국내 SIP 회선 + 중계 서버(Asterisk)** | 아직 없습니다. 지금은 관리 화면에서 브라우저로 통화하는 웹 테스트만 있습니다([6-web-test.md](6-web-test.md)) |

- **가장 큰 장애물은 전화 회선입니다.**
  - Twilio 같은 해외 통신사로 한국 휴대폰에 걸면 국제전화로 표시되거나 막힙니다.
  - 국내 통신사(KT·SKB·LGU+ 또는 국내 통신 API 업체)와 회선 계약이 필요합니다.
  - **모델 선택보다 먼저 견적과 기술 조건을 받아야 합니다.**
- **비용:** 모델 비용은 분당 30원 안팎, 회선을 포함하면 **분당 약 110∼145원**입니다(추정, 9장). vox 공개 가격은 분당 약 340원입니다. 대신 개발과 운영 인력이 듭니다. STT를 PoC에서 쓰는 Soniox로 잡으면 분당 약 14원이 더 줄어듭니다(9장).

### 2-3. 정리: 무엇을 가져오나

| 구분 | 업체가 한 것 | 우리가 할 것 |
|---|---|---|
| 기초 모델 (STT/LLM/TTS) | 외부 API 조합. 일부는 자체 호스팅 | **외부 API 조합** (나중에 일부 자체 호스팅 검토) |
| 실시간 파이프라인 | LiveKit Agents 포크 | **LiveKit Agents 그대로 사용** + 설정 튜닝. 지금은 Soniox 플러그인에 작은 패치 하나만 얹었습니다(4-2) |

## 3. 구조 선택: 단계 연결형 vs 음성 직통형

| 항목 | 단계 연결형 (STT → LLM → TTS) | 음성 직통형 (Realtime) |
|---|---|---|
| 대표 모델 | 부품을 각각 고름 | OpenAI `gpt-live-1`(2026-09), `gpt-realtime-2.1`, Google `gemini-3.8-live` |
| 한국어 부품 선택 | 자유 (RTZR, Typecast 등 국내 업체 가능) | 모델에 고정 |
| 제품명 인식·발음 | 키워드 부스팅과 발음 변환으로 강하게 제어 | 프롬프트로만 제어 |
| 대화 기록·감사 | 텍스트가 단계마다 남아 필터링·기록이 쉬움 | 별도 받아쓰기 필요 |
| 목소리 | 직원 목소리 복제 가능 | 정해진 음성 위주 |
| 자연스러움 (끼어들기) | 직접 튜닝해야 함 | 좋음 |
| 지연 | 약 0.8∼1.4초 | 약 0.8∼1.5초 |
| 분당 모델 비용 | 약 $0.01∼0.035 | 약 $0.015∼0.07 |
| 구축 난이도 | 중간 (프레임워크 사용) | 낮음 |

(2026-11-08 추가) 표의 지연과 비용은 조사 자료의 값입니다. 이 레포의 PoC에서 단계 연결형으로 잰 값은 고객 말이 끝나고 본 답의 첫소리까지 약 1.4초이고, 짧은 즉시 반응("네네.")을 먼저 들려줘 고객이 느끼는 침묵은 약 0.6∼0.8초입니다(8장, [5-poc-results.md](5-poc-results.md)). 음성 직통형은 재지 않았습니다.

**추천: 단계 연결형.**
- vox와 같은 방식입니다.
- 영업 통화에서는 **제품명("F2 울트라", "메탈팹", "엑스툴")과 가격을 정확히 듣고 말하는 것**이 중요합니다. 단계 연결형이 이 부분을 제어하기 쉽습니다.
- 대화 기록 대응도 쉽습니다.

**음성 직통형은 비교용으로만 테스트합니다.**
- `gpt-live-1`은 발신 SIP를 직접 지원하고 대화 전환이 0.8초 수준이라는 2차 자료가 있습니다.
- 다만 국내 회선이 TLS·SRTP·Opus를 지원해야 하고, 한국어 품질 공식 자료는 없습니다.

## 4. 부품 선택

- 우리 지식(기기 소개, 가격, FAQ)은 수만 자 수준이라 **처음에는 RAG 없이 프롬프트에 그대로** 넣습니다. RAG(검색 증강 생성)는 질문마다 문서에서 관련 부분을 찾아 프롬프트에 붙이는 방식입니다. vox도 1만 토큰 미만은 그대로 넣습니다. (지금 코드) `knowledge/xtool.md`를 지시문에 그대로 넣는 구조만 있고, 상담팀이 채우기 전이라 내용은 비어 있습니다(`src/knowledge.ts`).

### 4-5. 턴 감지와 끼어들기

**턴 감지**는 고객 말이 끝나 AI가 답할 차례인지 정하는 일이고, **끼어들기**는 AI가 말하는 도중에 고객이 말을 시작하는 일입니다([학습서 7장](1-study/07-turn-taking.md)). 한국어는 "네", "음", "아" 같은 **맞장구가 잦은 언어**입니다. 단순히 소리만 감지하면 AI가 자꾸 말을 멈춥니다. vox가 가장 공들인 부분도 여기입니다.

| 단계 | 사용할 것 | 근거 |
|---|---|---|
| 소리 감지 | Silero VAD (30ms 처리에 1ms 미만, 8kHz 지원) | (확인) |
| 말 끝 판단 | LiveKit 오디오 턴 감지 모델 (한국어 포함 14개 언어) | (확인) 한국어 정확도는 미공개 |
| 맞장구와 끼어들기 구분 | LiveKit Adaptive Interruption | (확인) 영어에서 더 낫다고 명시 |
| 우리가 튜닝할 것 | 맞장구 무시어 목록("네", "예", "음", "아", "그렇죠"), 끼어들기 최소 길이 약 0.5초, "아니요"·"잠깐만요" 같은 말은 즉시 멈춤, 전화번호를 불러줄 때는 더 기다림 | vox·ElevenLabs 설정 참고 |

- 참고: 말 끝 판단 대기를 0.3초로 짧게 잡으면 말이 중간에 잘리는 비율이 40∼52%였다는 외부 실측이 있습니다. vox 기본 무음 기준은 0.5초입니다.

(2026-11-08 추가, 지금 코드) 위 계획 가운데 지금 들어간 것과 다른 것입니다.

- **소리 감지:** SDK에 번들된 Silero VAD를 따로 설치 없이 씁니다. 16kHz 소리를 512샘플(32ms) 창마다 판단합니다([학습서 5장](1-study/05-vad.md)).
- **말 끝 판단 대기:** SDK 기본값을 그대로 씁니다. 턴 감지 모델이 "끝났다"고 보면 최소 0.3초, 아니면 최대 2.5초를 기다립니다. 0.3초는 하한이고, 실제 턴 확정은 Soniox의 확정 글이 도착할 무렵(PoC 0.38∼0.54초)입니다([학습서 7-4](1-study/07-turn-taking.md#7-4-이-프로젝트의-말-끝-판단-한-턴의-타임라인)). 이 레포는 0.3초를 턴 감지 모델이 끝났다고 볼 때만 쓰므로, 위 외부 실측과 조건이 같은지는 확인하지 않았습니다.
- **끼어들기 최소 길이:** 0.5초가 아니라 0.2초입니다(`src/main.ts`의 `minDuration: 200`). 0.3초에서 멈추기까지 약 0.4초가 걸려 더 줄였습니다([5-poc-results.md](5-poc-results.md)).
- **맞장구 무시어 목록:** 두지 않았습니다. 맞장구와 진짜 끼어들기의 구분은 적응형 끼어들기 모델에 맡깁니다. 이 모델은 개발 모드와 LiveKit Cloud 배포에서만 기본으로 켜지고, 직접 운영(`start`)에서는 `src/main.ts`의 `interruption` 옵션에 `mode: 'adaptive'`를 넣어야 켜집니다.
- **전화번호를 불러 줄 때 더 기다리기:** 아직 없습니다.

### 4-6. 자동응답·음성사서함 감지

부재중이면 통신사 안내("전화를 받을 수 없어…", 소리샘)가 나옵니다. 이걸 사람으로 착각하면 AI가 혼자 떠듭니다.

1. **SIP 응답 코드로 먼저 거릅니다.** 통화 중(486), 응답 없음(480) 등. 연결 전 미리 나오는 안내음(early media)은 대화로 취급하지 않습니다.
2. **연결 후 키워드로 빠르게 판정합니다.** "소리샘", "음성사서함", "삐 소리 후", "전원이 꺼져", "받을 수 없어"
3. **애매하면 LiveKit 자동응답 감지에 한국어 프롬프트를 넣어** 판정합니다.
4. **사서함이면 끊습니다.** 대신 문자(Solapi)를 보내고 재시도 일정을 잡습니다.
5. 처음 2∼4주는 실제 녹음을 모아 기준을 조정합니다.

(2026-11-08 기준) 아직 만들지 않았습니다. 전화 연결 단계(10장의 2단계)에서 통신사의 응답 코드와 안내 멘트 샘플을 받아 만듭니다. SIP 응답 코드와 early media(연결 전에 흐르는 안내음)는 [학습서 3-5](1-study/03-transport.md#응답-코드가-알려-주는-것)에 풀어 두었습니다.

## 5. 전화 회선: 가장 큰 장애물

### 5-1. 해외 통신사는 안 됩니다

| 사업자 | 문제 |
|---|---|
| Twilio | 한국 번호는 한국 사업자등록 기업만 개통할 수 있고, 국내 번호 표시가 보장되지 않습니다. |
| Vonage | 해외 발신은 "006 1415…"처럼 국제전화 식별번호가 붙어 표시됩니다. |
| Retell (해외 AI 콜 업체) | 한국 발신을 지원하지 않습니다(2026-05). 직접 SIP로 우회하라고 안내합니다. |

- 방통위 가이드라인에 따라 **해외 발신 전화는 휴대폰에 00X가 붙어 표시**됩니다.
- 2026년 5월 해외 번호를 국내 번호로 위장하는 행위를 금지하는 법 개정안이 국무회의를 통과했습니다(위반 시 3년 이하 징역).
- **결론: 회사 번호로 걸려면 국내 통신사 회선이 필수입니다.**

### 5-2. 국내 선택지

| 선택지 | 내용 | 확인 수준 |
|---|---|---|
| KT 기업 인터넷전화 / SIP 트렁크 | 070 기본료 2,000∼4,000원, 통화료 초당 1.5원(VAT 별도). 인증은 ID/PW, 고정 IP, SBC 연동 중 선택 | 대리점 페이지 기준, 공식 견적 필요 |
| SK브로드밴드 교환기형 | 채널당 월 2,000원, 30채널 단위 | 판매 대행 페이지 기준 |
| LG U+ | 자체 AI 콜봇 상품이 있습니다(OpenAI 기반, 2025-12). SIP 상품 상세는 미확인 | 미확인 |
| 한국AI통신 (ClawOps) | REST API로 070·대표번호를 발급합니다. 모든 요금제에 SIP 포함, AWS 서울, 월 ₩19,000∼99,000 | **업체 홍보 자료 기준, 검증 필요** |
| Solapi 음성 메시지 | TTS 단방향 발송만 됩니다. 실시간 대화에는 쓸 수 없습니다. | 확인 |

### 5-3. 연결 방법

LiveKit SIP는 **등록(REGISTER) 방식을 지원하지 않습니다.** 국내 회선은 ID/PW 등록 방식이 많습니다. 그래서 중간에 중계 서버를 둡니다.

```text
국내 회선 (KT/SKB/LGU+ 등)
   ⇅  등록 방식, G.711 A-law
[중계 서버] Asterisk(또는 jambonz), GCE 서울 VM, 고정 공인 IP
   ⇅  IP 인증 SIP, 코덱 변환, NAT·SRTP 처리
[LiveKit SIP]
```

그림은 위에서 아래로 국내 회선 → 중계 서버 → LiveKit 순서이고, `⇅` 옆의 글은 그 구간에서 쓰는 연결 방식입니다. G.711, SRTP, NAT 같은 말은 [학습서 17-1 용어집](1-study/17-glossary-and-next.md#17-1-용어집)과 [학습서 3-5](1-study/03-transport.md#3-5-sip-전화를-거는-대화)에 있습니다.

- 고정 IP 인증 회선이면 LiveKit SIP에 바로 붙일 수도 있습니다. 하지만 코덱, NAT, 암호화 차이를 흡수하려면 **중계 서버를 두는 쪽이 안전합니다.**
- 나중에 대표번호 인바운드를 붙일 때도 중계 서버에서 라우팅만 추가하면 됩니다.
- 참고 사례: 국내 공공 프로젝트(GovTech-Korea)도 Asterisk + 070 연동이 어려워 MVP에서 뺐습니다. **회선 연동은 일정에 여유를 둬야 합니다.**

### 5-4. 통신사에 물어볼 것

> 요구 사항 상세, 문의 메일 초안, 세팅 순서는 [7-telephony-setup.md](7-telephony-setup.md)에 있습니다.

1. 최소 채널 수 (1∼2채널 계약 가능한지)
2. 인증 방식 (고정 IP / ID·PW 등록)
3. 지원 코덱 (G.711 A-law/μ-law, Opus), 암호화(SRTP) 지원
4. 발신번호로 대표번호나 02 번호를 쓸 수 있는지, 레터링(상호 표시) 가능 여부
5. 동시 통화 수
6. **AI 콜봇·자동 발신 용도를 약관상 허용하는지**
7. 통화료 (휴대폰 발신 단가)

### 5-5. 받는 비율 올리기

- 070보다 **대표번호나 02 번호**가 받는 비율이 높을 것으로 봅니다(추정).
- KT 발신정보알리미 같은 상호 표시 서비스를 씁니다.
- 문의 직후 Solapi로 **"오리지널스에서 곧 전화드립니다" 문자를 먼저 보냅니다.**
- 후후·T전화에 업체 정보를 등록합니다(절차 확인 필요).

```text
[웹사이트 문의 폼]
   │
   ▼

[LiveKit]  미디어 + SIP  (LiveKit Cloud 일본 리전, 또는 서울 VM 직접 운영)
   ⇅
[중계 서버] Asterisk, GCE 서울 VM  ⇄  국내 SIP 회선  ⇄  고객 휴대폰
```

| 품질 검수 화면, 지표 | 웹 테스트 화면이 방금 한 통화의 요약·판정·지연·대화록을 보여 줍니다. 통화 목록과 녹음 재생은 아직입니다. 구간별 지연은 통화마다 기록합니다(8장) |
| 시나리오 테스트 | 표에서는 "나중"이지만, 텍스트 시뮬레이션 시나리오 6개가 먼저 생겼습니다(`scenarios.yaml`). 비용 때문에 CI에서는 돌리지 않습니다 |

(2026-11-08 추가) **무응답 재촉과 종료: 계획과 지금 코드.** 계획은 "10초 조용하면 '여보세요?', 30초면 종료"였습니다. 지금 코드(`src/call-guard.ts`)는 이렇게 동작합니다([학습서 5-5](1-study/05-vad.md#away를-쓰는-무응답-안전장치-2026-11-03-추가)).

1. 고객이 말하지 않고 AI도 말하거나 답을 준비하지 않는 상태(둘 다 `listening`)로 10초가 지나면, 세션이 고객 상태를 `away`(자리 비움)로 바꿉니다. 10초는 `AgentSession`의 `userAwayTimeout`이고, 코드에서는 `USER_AWAY_TIMEOUT_SEC`입니다.
2. `away`가 되면 "여보세요? 제 목소리 잘 들리세요?"를 재생합니다. 고객이 이 말 도중에 대답하면 여기서 끝납니다.
3. 재생이 끝난 뒤 10초(`NO_RESPONSE_END_MS`) 안에 고객이 대답하지 않으면 작별 인사("통화가 어려우신 것 같아요…")를 하고 끊습니다. 대답은 VAD가 잡은 말 시작이든, VAD가 놓치고 STT만 잡은 작은 말이든 셉니다(2026-11-08부터).

그래서 침묵이 시작된 뒤 작별 인사가 나오기까지는 약 20초에 재촉 문장의 재생 시간(몇 초)을 더한 길이입니다(코드에서 계산, 재지 않음). 통화 최대 길이는 8분이고(`MAX_CALL_MS`), 넘으면 정해진 인사 뒤 끊습니다.

알아 둘 점: 고객 말이 끝나고 즉시 반응 "네네."가 재생을 마치면, AI의 본 답을 기다리는 동안에도 이 10초 시계가 돕니다. AI 상태가 그 사이 다시 `listening`이 되기 때문입니다. 처음 코드는 본 답이 즉시 반응 뒤 10초 넘게 소리를 내지 못하면 "여보세요?"를 냈고, 늦게라도 성공한 본 답 바로 뒤에 이어서 내기도 했습니다. 2026-11-08부터 `guardCall`은 본 답을 기다리는 동안 묻지 않고, 늦게 온 답을 말했으면 그 뒤로 10초를 다시 기다립니다. LLM이 실패했으면 즉시 반응 뒤로 이미 10초가 지난 경우 바로 묻습니다. 실제 SDK에 이 레포의 코드를 얹어 고치기 전과 뒤를 재현했습니다([학습서 11-6절 깊이 보기](1-study/11-session-pipeline.md#깊이-보기-본-답을-기다리는-동안-도는-10초-타이머-2026-11-08-추가)).

## 8. 응답 지연 예산

**목표: 고객 말이 끝나고 AI가 말을 시작할 때까지 1초 안팎.** 업체 수준은 0.6∼0.95초입니다.

| 구간 | 목표 | PoC에서 잰 값 (2026-11-03) | 줄이는 방법 |
|---|---|---|---|
| 말 끝 판단 | 0.3∼0.5초 | 0.38∼0.54초 (STT 확정 포함) | 턴 감지 모델로 짧게 판단하되 맞장구는 무시 |
| STT 확정 | 0.15∼0.3초 | 따로 재지 않음 (말 끝 판단 안에 들어 있음) | 스트리밍, 말 끝나면 바로 확정 요청 |
| LLM 첫 토큰 | 0.2∼0.4초 | 약 0.8초 (0.77∼0.92초) | 생각 모드 끔, 프롬프트 캐시, 아시아 리전이나 빠른 제공자 |
| TTS 첫 음성 | 0.1∼0.2초 | 약 0.17초 | 문장 단위로 끊어 바로 합성, **TTS 연결을 미리 열어 둠** |
| 네트워크 | 0.05∼0.1초 | 재지 않음 | 워커·STT·TTS를 가까운 리전에 |

표 읽는 법: "목표"는 계획 때 정한 구간별 몫이고, "PoC에서 잰 값"은 맥(서울)에서 해외 API로 잰 값입니다([5-poc-results.md](5-poc-results.md)). STT 확정은 말 끝 판단 안에 들어 있으므로 다섯 줄을 모두 더하면 두 번 셉니다([학습서 13-2](1-study/13-latency.md#13-2-지연-예산-직렬-구간의-합)). PoC에서 잰 세 구간을 더한 본 답 첫소리까지는 약 1.4초로 목표보다 길고, 가장 큰 몫은 LLM 첫 토큰입니다. 고객이 처음 듣는 소리는 즉시 반응 "네네."라서 체감 침묵은 약 0.6∼0.8초입니다.

- 외부 실측 사례에서는 **TTS가 전체 지연의 60∼85%를 차지**했습니다. 이 레포 PoC에서는 TTS 첫 음성이 약 0.17초로 작았습니다.
- 부품들을 같은 리전에 모으자 1.6초에서 크게 줄었다는 외부 사례도 있습니다.
- 서울에서 미국 API까지 왕복은 재지 않았고, 대략 130∼200ms로 봅니다. 견주어 서울↔AWS 도쿄 왕복은 실측 약 40ms(39∼44ms)입니다([학습서 13-2절 깊이 보기](1-study/13-latency.md#깊이-보기-왕복rtt으로-세는-네트워크-비용-2026-11-06-추가)).
- **구간별 지연을 매 통화 기록**해서(vox도 함) 병목을 찾습니다. (지금 코드) 말 끝 판단·LLM 첫 토큰·TTS 첫 음성을 턴마다 모아 통화 결과로 functions-xtool에 보냅니다(`src/call-result.ts`).
- 도구를 호출하는 동안(예약 조회)은 "잠시만요, 확인해 볼게요"를 말해 공백을 메웁니다.
