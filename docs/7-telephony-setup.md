# 전화 회선 준비 가이드 — 통신사 요구 사항과 세팅 순서

AI 상담 에이전트가 고객 휴대폰으로 전화를 걸려면 **국내 통신사의 SIP 회선**이 필요합니다. 이 문서는 아래 네 가지를 다룹니다.

1. 통신사에 무엇을 요구할지
2. 문의 메일 초안
3. 답변을 받고 판단하는 방법
4. 회선을 받은 뒤 세팅하는 순서

> - 왜 국내 회선이 필요한지, 전체 구조는 [2-tech-stack.md 5장](2-tech-stack.md#5-전화-회선-가장-큰-장애물)에 있습니다.
> - 설정 예시는 구조를 보여 주기 위한 것입니다. 실제 값(IP, 도메인, 계정, 번호 형식)은 통신사가 보내 주는 **연동 규격서**를 따릅니다.

## 1. 한 줄 요약

**"IP-PBX(Asterisk) 연동용 기업 SIP 트렁크, 동시 통화 2~4회선, 070(또는 대표번호) 발신 표시, G.711 코덱, 클라우드 서버(GCP 서울)에서 인터넷으로 연동 가능"**을 요구합니다.

가장 중요한 질문은 마지막 조건입니다. **우리 클라우드 서버에서 인터넷으로 붙을 수 있는지** 꼭 물어야 합니다. 국내 SIP 상품 중에는 그 통신사의 인터넷 회선 위에서만, 사무실에 장비를 설치해야만 제공되는 것이 많습니다.

## 2. 문의 전에 우리 쪽에서 확인할 것

| 항목 | 확인 이유 |
|---|---|
| **기존 대표번호(15xx/02 등)가 어느 통신사인지** | 대표번호를 발신 표시로 쓰려면 같은 통신사일 때 쉬운 경우가 많습니다(추정). 먼저 그 통신사에 문의합니다. |
| **사무실 인터넷이 어느 통신사인지** | 5장의 B안(사무실 설치)으로 갈 경우 필요합니다. |
| 사업자등록증, 담당자 연락처 | 가입 서류 |
| 예상 통화량 | 일 발신 건수, 동시에 걸 통화 수. 파일럿은 하루 수십 건, 동시 2~4통이면 충분합니다. |
| 서버 위치 | GCP 서울 리전(asia-northeast3)에 고정 공인 IP를 받을 예정이라고 전달합니다. |

## 3. 통신사에 요구할 것

### 3-1. 필수

| 항목 | 우리가 원하는 값 | 이유 |
|---|---|---|
| **상품** | 기업용 SIP 트렁크 (IP-PBX 연동용). 일반 070 전화기 상품은 아님 | 서버가 직접 전화를 걸고 받아야 합니다. |
| **연동 위치** | **인터넷 경유로 클라우드 서버(GCP 서울)에서 연동** | 가장 중요합니다. 안 되면 5장의 B·C안으로 갑니다. |
| **동시 통화 수(채널)** | 파일럿 2~4채널, 나중에 10채널 이상으로 늘릴 수 있는지 | 동시에 걸 수 있는 통화 수입니다. |
| **번호** | 070 번호 1~2개 신규 발급 | 발신 표시와 수신에 씁니다. |
| **발신 표시** | 070 번호로 표시. 가능하면 **기존 대표번호로 표시** | 고객이 아는 번호여야 받습니다. |
| **인증 방식** | **고정 IP 인증**을 선호. 안 되면 ID/PW 등록(REGISTER)도 가능 | 우리 중계 서버(Asterisk)는 둘 다 됩니다. |
| **연동 정보** | 통신사 SBC의 IP·도메인, 포트, 전송 방식(UDP/TCP/TLS) | 서버 설정에 필요합니다. |
| **코덱** | G.711 A-law 또는 μ-law. ptime 20ms | AI 음성 처리 표준입니다. G.729만 되는 상품은 피합니다. |
| **DTMF** | RFC 2833/4733 방식 | 버튼 입력이 필요할 때 씁니다. |
| **용도 허용** | **AI 음성 상담 시스템으로 자동 발신**해도 약관상 문제없는지 | 나중에 회선이 정지되면 안 됩니다. |
| **요금** | 월 기본료, 채널료, 설치비, 약정 조건, **휴대폰·유선 발신 통화료와 과금 단위(초/10초/분)** | 비용 계산용입니다. |
| **기술 지원** | 연동 테스트 지원, 기술 담당자 연락처, 장애 대응 시간 | 처음 연동할 때 꼭 필요합니다. |

### 3-2. 있으면 좋은 것

| 항목 | 내용 |
|---|---|
| 레터링 / 발신정보 표시 | 받는 사람 화면에 "오리지널스" 표시 (예: KT 발신정보알리미) |
| 암호화 | SIP over TLS, SRTP 지원 여부. 인터넷 경유라면 권장 |
| 착신 | 나중에 대표번호로 걸려 온 전화를 이 회선으로 받을 수 있는지 |
| 통화 전환 | 통화 중 상담사 휴대폰으로 넘기는 SIP REFER 지원 여부. 안 되면 우리 서버에서 두 통화를 이어 처리합니다. |
| 통화 결과 코드 | 통화 중·부재·결번일 때 어떤 SIP 응답 코드(486/480/404 등)를 주는지, 안내 멘트를 연결 전(183)에 흘리는지 | 부재·사서함 판단에 씁니다. |
| 테스트 기간 | 약정 전에 시험 개통이 되는지 |
| 스팸 정책 | 발신량이 많을 때 통신사가 차단하는 기준 |

## 4. 문의 메일 초안

통신사 기업 영업 담당에게 그대로 보내도 됩니다. 대괄호 부분만 채우세요.

```
제목: AI 음성 상담 시스템 연동용 기업 SIP 트렁크 견적 문의

안녕하세요. 주식회사 오리지널스 [이름]입니다.
고객 상담 신청에 회신하는 AI 음성 상담 시스템을 자체 개발하고 있어,
연동할 기업 SIP 트렁크 상품의 견적과 기술 조건을 문의드립니다.

[사용 목적]
- 웹사이트에서 상담을 신청한 고객에게 AI 상담원이 전화를 걸어 1차 상담을 진행합니다.
- 상담을 신청하지 않은 불특정 다수에게는 발신하지 않습니다.
- 추후 대표번호 수신 전화 응대도 검토하고 있습니다.

[시스템 구성]
- 서버: Google Cloud 서울 리전, 고정 공인 IP
- 교환기: Asterisk (IP-PBX)
- 예상 규모: 초기 동시 통화 2~4회선, 일 발신 [수십~수백]건. 추후 10회선 이상으로 확장 예정

[문의 사항]
1. 위와 같이 클라우드 서버에서 인터넷을 통해 SIP 트렁크 연동이 가능한지요?
   (불가하다면 필요한 회선·장비 조건을 알려 주세요.)
2. 인증 방식: 고정 IP 인증이 가능한지, ID/PW 등록 방식인지요?
3. 연동 규격: SBC 주소, 포트, 전송 방식(UDP/TCP/TLS), 지원 코덱(G.711 A-law/μ-law),
   DTMF 방식, SRTP 지원 여부
4. 최소 계약 회선 수와 회선 추가 방법
5. 070 번호 발급과, 기존 대표번호 [번호]를 발신 표시로 쓸 수 있는지
   (필요 서류 포함), 레터링(상호 표시) 서비스 여부
6. AI 음성 시스템의 자동 발신 용도가 약관상 허용되는지
7. 요금: 월 기본료, 회선료, 설치비, 약정 조건, 휴대폰·유선 발신 통화료와 과금 단위
8. 통화 중·부재·결번 시 SIP 응답 코드, 통화 전환(SIP REFER) 지원 여부
9. 연동 테스트 지원과 시험 개통 가능 여부

연동 규격서가 있으면 함께 보내 주시면 감사하겠습니다.

주식회사 오리지널스 [이름] / [연락처] / [이메일]
```

**어디에 보낼지**

| 대상 | 메모 |
|---|---|
| 기존 대표번호 통신사 | 발신 표시 문제 때문에 1순위입니다. |
| KT 기업 인터넷전화(SIP) | 대리점 기준 070 기본료 2,000~4,000원, 초당 1.5원. 공식 견적 필요 |
| SK브로드밴드 교환기형 | 채널당 월 2,000원, 30채널 단위라는 판매 대행 정보. 최소 단위 확인 필요 |
| LG U+ | SIP 상품 상세 미확인 |
| 한국AI통신(ClawOps) 같은 국내 통신 API 업체 | API로 070 발급, SIP 포함, 클라우드 연동 전제. **홍보 자료만 확인했으므로 검증 필요.** 큰 통신사가 클라우드 연동을 거절할 때의 대안입니다. |

2~3곳에 동시에 보내서 비교하는 것을 추천합니다.

## 5. 답변을 받고 판단하는 법

| 답변 | 선택 | 구성 |
|---|---|---|
| **인터넷 경유 클라우드 연동 가능** | **A안 (추천)** | GCP 서울 VM에 Asterisk를 두고 통신사 SBC와 직접 연결 |
| 그 통신사의 인터넷 회선 위에서만 가능 (사무실 설치) | B안 | 사무실 회선에 작은 서버나 SBC를 두고, 사무실 서버와 GCP를 VPN으로 연결. 사무실 정전·인터넷 장애가 곧 서비스 장애가 됩니다. |
| 큰 통신사가 모두 어렵거나 너무 비쌈 | C안 | 국내 통신 API 업체의 SIP를 씁니다. 연동이 쉽지만 업체 안정성을 검증해야 합니다. |
| AI 자동 발신이 약관상 불가 | — | 그 상품은 제외합니다. |

**판단 기준 우선순위**
1. 클라우드 연동 가능 여부
2. AI 발신 허용
3. 대표번호 발신 표시
4. 최소 회선 수와 요금
5. 기술 지원

## 6. 세팅 순서

전체 흐름은 다음과 같습니다.

```
고객 휴대폰 ⇄ 통신사 SBC ⇄ [Asterisk, GCE 서울] ⇄ [LiveKit SIP] ⇄ AI 에이전트
```

### 6-1. 서버 준비 (회선 개통 전에 해 둘 수 있음)

1. **GCE VM 생성**
   - 리전: 서울(asia-northeast3)
   - 사양: e2-small~medium 정도(파일럿 기준)
   - OS: Ubuntu LTS
2. **고정 외부 IP 예약**
   - 이 IP를 통신사에 알려 줍니다(IP 인증일 때).
3. **방화벽**: 허용할 IP만 엽니다.

   | 포트 | 허용 대상 |
   |---|---|
   | SIP 5060 UDP/TCP (TLS면 5061) | **통신사 SBC IP, LiveKit SIP IP만** |
   | RTP 10000~20000 UDP | 통신사 미디어 IP, LiveKit |
   | SSH | 회사 IP만 |

4. **Asterisk 설치**
   - LTS 버전, PJSIP 사용
   - `sngrep`(SIP 메시지 확인 도구)도 같이 설치합니다.

### 6-2. 통신사 연결 (개통 후)

통신사 규격서의 값으로 `pjsip.conf`를 씁니다. 아래는 **ID/PW 등록 방식 예시**입니다.

```ini
; 공통 전송 — GCE는 1:1 NAT라 외부 IP를 명시해야 음성이 들립니다
[transport-udp]
type=transport
protocol=udp
bind=0.0.0.0:5060
external_media_address=<고정 외부 IP>
external_signaling_address=<고정 외부 IP>
local_net=10.0.0.0/8

; ── 통신사 ──
[carrier-auth]
type=auth
auth_type=userpass
username=<통신사 계정>
password=<통신사 비밀번호>

[carrier-reg]                       ; IP 인증 방식이면 이 블록은 필요 없습니다
type=registration
transport=transport-udp
outbound_auth=carrier-auth
server_uri=sip:<통신사 SBC 주소>
client_uri=sip:<통신사 계정>@<통신사 도메인>

[carrier-aor]
type=aor
contact=sip:<통신사 SBC 주소>

[carrier]
type=endpoint
transport=transport-udp
context=from-carrier
disallow=all
allow=alaw,ulaw
direct_media=no
dtmf_mode=rfc4733
outbound_auth=carrier-auth
aors=carrier-aor
from_user=<발신 번호 또는 계정>
from_domain=<통신사 도메인>

[carrier-identify]
type=identify
endpoint=carrier
match=<통신사 SBC IP>
```

**확인:**
- `pjsip show registrations`가 Registered로 나오는지 봅니다.
- **LiveKit을 붙이기 전에 소프트폰으로 먼저 시험합니다.** Zoiper나 MicroSIP를 Asterisk 내선으로 등록하고 직원 휴대폰에 걸어 봅니다. 이 단계에서 소리가 안 들리면 대부분 NAT 설정(`external_*_address`)이나 RTP 방화벽 문제입니다.

### 6-3. 발신 규칙 (dialplan)

`extensions.conf`에 **국내 휴대폰 번호만** 나가도록 씁니다.

```ini
[from-livekit]
; LiveKit은 +8210… 형식으로 보낼 수 있어 010…으로 바꿔 줍니다
exten => _+8210XXXXXXXX,1,Goto(from-livekit,0${EXTEN:3},1)

exten => _010XXXXXXXX,1,Set(CALLERID(num)=<발신 표시 번호>)
 same => n,Set(GROUP()=outbound)
 same => n,GotoIf($[${GROUP_COUNT(outbound)} > 4]?busy)   ; 동시 발신 상한
 same => n,Dial(PJSIP/${EXTEN}@carrier,45)
 same => n,Hangup()
 same => n(busy),Hangup(17)

; 그 밖의 번호(국제전화, 060 등)는 규칙이 없으므로 나가지 않습니다
```

- 통신사가 원하는 번호 형식(010…, +82…, 앞자리 접두어)은 규격서를 따릅니다.

### 6-4. LiveKit 연결

**LiveKit → Asterisk 구간**은 두 방식 중 하나를 고릅니다.

| 방식 | 내용 |
|---|---|
| LiveKit Cloud SIP (PoC에 간편) | LiveKit 아웃바운드 트렁크에 계정(ID/PW)을 넣고, Asterisk가 그 계정으로 인증합니다. LiveKit Cloud 일본 리전을 씁니다. |
| LiveKit SIP를 서울에 직접 운영 | 같은 VPC 안에서 내부 IP로 인증합니다. 가장 단순하고 지연도 짧습니다. 대신 LiveKit 서버를 직접 운영해야 합니다. |

LiveKit 아웃바운드 트렁크 예시 (`lk` CLI):

```json
{
  "trunk": {
    "name": "asterisk-seoul",
    "address": "<Asterisk 고정 외부 IP>:5060",
    "numbers": ["<발신 표시 번호>"],
    "authUsername": "<LiveKit용 계정>",
    "authPassword": "<LiveKit용 비밀번호>"
  }
}
```

```bash
lk sip outbound create outbound-trunk.json      # 트렁크 id를 받습니다
```

- Asterisk 쪽에는 이 계정으로 들어오는 `from-livekit` 엔드포인트를 만듭니다. 계정 인증으로 찾으려면 `endpoint_identifier_order`에 `auth_username`을 넣습니다.

**발신 시험:**
- 에이전트를 배정한 방(room)에 SIP 참가자를 만들면 전화가 나갑니다.
  - 입력값: `sip_trunk_id`, `sip_call_to` = 고객 번호, `room_name`
- 실제 서비스에서는 functions-xtool이 이 API를 부릅니다([2-tech-stack.md 6장](2-tech-stack.md#6-전체-아키텍처)).

### 6-5. 수신 (나중에)

대표번호 응대를 시작할 때 추가합니다.

1. 통신사 착신 설정
2. Asterisk `from-carrier`에서 LiveKit으로 넘기는 규칙

## 7. 보안: 요금 폭탄 막기

SIP 서버는 인터넷에 열리는 순간 **국제전화 무단 발신 공격**을 받습니다. 하룻밤에 수백만 원이 나오는 사고가 실제로 흔합니다.

- **방화벽:** SIP 포트는 통신사와 LiveKit IP만 허용합니다(6-1).
- **발신 규칙:** 010 국내 휴대폰만 나가게 합니다. 국제전화와 060은 규칙에서 빼 둡니다(6-3).
- **통신사 측 차단:** 회선에서 **국제전화 발신 차단**을 신청합니다.
- **동시 발신 상한:** dialplan과 통신사 계약 양쪽에 둡니다.
- **계정:** 긴 무작위 비밀번호를 쓰고, `fail2ban`으로 인증 실패를 반복하는 IP를 차단합니다.
- **알림:** 통화 상세 기록(CDR)을 보고 하루 발신량이나 금액이 기준을 넘으면 알립니다.
- **비밀값:** 통신사 계정은 저장소에 커밋하지 않고 서버 환경변수나 Secret Manager에 둡니다.
